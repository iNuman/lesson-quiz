# JLPT N5 Kanji & Reading track

A second study track beside the vocabulary lessons (open it with the **N5 Kanji** switch under the header, or `#/n5`).
It is **not** another kanji quiz: its aim is that a learner can read and answer N5-level questions, so it never treats
one correct tap as knowing a kanji.

> **Status: Phases 1–2 of 5 (a vertical slice).** 18 kanji over 3 days, with full learning, practice, recall, adaptive review
> and persistence. Not yet built (and not claimed): kanji for the rest of N5, grammar lessons, unfamiliar-passage tests, timed
> mock exams, listening. See *What is not here yet*.

## How learning works

Each day (default **6 new kanji**, configurable 3–10) is one coherent journey:

| Step | What happens |
| --- | --- |
| Warm-up review | The kanji that are due, capped (default 10). Each question targets the learner's weakest required skill. |
| New kanji | A horizontal row of kanji with hiragana above each. Meaning, on'yomi/kun'yomi, vocabulary, an example sentence. |
| Sentences | Natural example sentences using only kanji met so far. Readings and English are toggled per sentence. |
| Reading | An original passage using the day's kanji (kanji not yet met always keep their furigana). |
| Check understanding | Authored comprehension questions about the passage. |
| Practice | Two differently-typed questions per kanji (meaning, reading in context, orthography, fill-in-the-blank, word meaning). |
| Recall | Typed hiragana readings (no choices), then self-check cards. |

Reading visibility has a global switch plus per-kanji, per-sentence and per-passage switches. Unfamiliar kanji always show
their reading.

### Recognition is not mastery

Per kanji the app stores first exposure, attempts, correct/wrong, hint use, five skill scores (meaning, reading, words,
context, recall), verified typed recalls, a spaced-repetition box and last/next review (`js/n5/model.js`).

* A correct answer **with a hint** earns half credit, never advances the schedule and is never counted as an unaided review day.
* A self-assessed "Knew it" earns 3/4 credit and can never, on its own, make a kanji mastered.
* **Mastered** needs meaning ≥ .65, reading ≥ .65, context ≥ .6 and recall ≥ .6 (two clean successes each), at least one verified typed
  recall, unaided successes on two or more different days and a solid review box. A later mistake demotes it; long neglect marks it *fading*.
* A box only advances when a review is actually due, and at most once a day, so repeating a question cannot launch a kanji to a 60-day interval.
* The day a kanji is introduced is a learning phase: it always comes back tomorrow.

Tests (`tests/n5/simulation.test.mjs`) prove: a hint-only learner never reaches *review* or *mastered*; a 95%-accurate learner
reaches mastery in weeks, not days; review load stays within the cap; weak and lapsed kanji return first.

### Typed answers

`js/n5/kana.js` normalises full-width/half-width, katakana→hiragana, whitespace/punctuation and romaji (Hepburn plus common
Nihon/Kunrei spellings, `nn`/`n'` for ん) — and nothing else. It never forgives a wrong reading (にぽん, にほ, おーきい ≠ おおきい).
Input that cannot be judged (kanji, gibberish, empty) is flagged and **not** recorded as an attempt.

### Readiness

`js/n5/readiness.js` reports demonstrated performance per area (vocabulary, kanji reading, orthography, grammar, unfamiliar
reading) from the answer log. It uses only distinct questions (repeating a familiar question adds nothing), counts hinted answers at half,
ignores self-checks and uses only recent evidence. Areas the release cannot test show "not in this release yet", and **no overall
figure is produced** until listening and mock exams exist (`capabilities` in `src/n5/meta.json`), so a readiness claim is impossible
by construction.

## Architecture

```
src/n5/            authored content (JSON) + verification.json
tools/build-n5.mjs validate + generate data/n5.js            (CI: --strict)
tools/verify-n5-sources.mjs  check against KANJIDIC2 + JMdict (needs network)
tools/n5-review-sheet.mjs    docs/n5-review-sheet.md for human reviewers
js/n5/             kana · markup · scheduler · model · questions · composer · readiness   (pure, no DOM, unit-tested)
js/n5/ui.js        all N5 rendering + events (#n5-root)
css/n5.css         N5 styles only
```

Integration with the existing app is deliberately small: `index.html` (switch, container, scripts), `js/app.js` (route
delegation + a keyboard guard, ~10 lines) and `js/game.js` (`awardXp`, `cue`, so N5 shares XP, level, streak and daily goal).
N5 progress lives in its own key, `jpquiz.n5.v1`; vocabulary progress is untouched. `data/lessons.js` is not read or written.

## Content format (`src/n5/`)

* `meta.json` – units (6 kanji each, in curriculum order), `capabilities`, `sources`, review notes.
* `kanji.json` – `id, meaning, meanings[], on[], kun[]` (KANJIDIC2 notation, e.g. `ひと.つ`, `-び`). Every reading/meaning must be a member of KANJIDIC2.
* `vocab.json` – `ruby` markup, `alt` readings, `en`, `lookalikes[]` (≥ 3 wrong spellings for orthography questions).
* `days/NN.json` – `sentences`, `cloze` (fill-in-the-blank, with hand-picked wrong words) and one `passage` with `questions`.

**Reading markup:** a kanji run followed by its hiragana in braces: `日本人{にほんじん}です`. *Every* kanji must carry a reading,
so the app can show or hide readings freely. Use furigana for kanji the learner has not met rather than forcing unnatural Japanese.

The build rejects (see `tests/n5/content.test.mjs`, which feeds it broken content): bare kanji, non-hiragana readings, malformed
markup, wrong answer indexes, duplicate options, too few look-alikes, readings that contradict `kanji.json`, a kanji without vocabulary,
two sentences, a passage appearance **and an item that tests it in context**, vocabulary using kanji outside the curriculum, and a
stale or missing source verification (`--strict`).

### Source verification

`node tools/verify-n5-sources.mjs` checks: every kanji reading/meaning against **KANJIDIC2**; every vocabulary spelling+reading against
**JMdict** (via the Jisho API); every kanji run used anywhere in sentences, passages and questions; and that no look-alike spelling is a
real word with the same reading (a second correct answer). It writes `src/n5/verification.json` with a content hash; the build compares the
hash, so changed content cannot ship with an out-of-date verification. It also records every JMdict reading of each spelling so wrong choices
can never be a real alternative reading (e.g. 一月 can also be read ひとつき).

Note: KANJIDIC2 tags 曜 as old level 3; it is included because 〜曜日 is core N5 vocabulary. (No official N5 kanji list exists.)

### What still needs human review

Sentences, passages, comprehension questions and fill-in-the-blank items are **original text, machine-checked for spelling and readings
only**. They need a proficient Japanese speaker for naturalness, level and answer uniqueness. The app labels them as such, and
`docs/n5-review-sheet.md` is a checklist of every item. Nothing is copied from textbooks or JLPT examinations.

## Question types and listening

`js/n5/questions.js` has a registry (`TYPES`) giving each type a `section`, an exam `area` and a mastery `skill`; each question is a
plain object with `prompt.kind`, `answerKind` (`choice` | `typed` | `self`), `hints[]` and `media: null`. To add **listening** later:

1. add `"listening": true` handling in `meta.json` `capabilities` and an optional `audio: { src, transcript }` on sentences/passages (the build already passes `audio` through);
2. register a type with `section: "listening"` and a builder that sets `prompt: { kind: "audio", … }` and `media`;
3. add a `prompt.kind === "audio"` branch in `promptHtml()` (`js/n5/ui.js`).

The composer, model, scheduler, readiness and storage need no changes.

## Commands

```
npm run build:n5     # validate + regenerate data/n5.js
npm run verify:n5    # re-check against KANJIDIC2/JMdict (network) → src/n5/verification.json
npm run test:n5      # unit + simulation + content tests (node:test, no dependencies)
node tools/n5-review-sheet.mjs
node serve.mjs 8000 & node tests/n5/browser-smoke.mjs   # end-to-end in Chrome/Edge (no dependencies)
```

## What is not here yet

grammar selection, sentence composition, text grammar, medium passages, information retrieval), timed mock exams, grammar lessons,
